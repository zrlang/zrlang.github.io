v0.5.0 打通的是**链路**：从源码一路到可烧录的固件，每一步都有实现。
但它是「框架完整」的状态 —— 循环不终止、寄存器串值、测试用例只有 8 个。

v0.6.0 是另一类工作：**不往前加东西，而是把中间层修对**。
修完之后，语言测试用例从 8 个涨到 25 个。

## 一条硬规则

语言用例是**自检程序**，宿主运行器会把每个用例在
`-O0` / `-O1` / `-O2` / `-O3` / `-Oz` 下各编译并运行一遍。

这条规则的价值在于：优化 pass 只要有一条改坏语义，用例就会在某个等级上变红。
「所有等级都通过」是一个比「跑通了一次」强得多的断言。

## SSA 构造：解开循环的那把钥匙

之前 `loop { ... break; }` 的状态是「编译成功，运行挂死」。根因有五个：

- `break` / `continue` 在 MIR 降级里落进 `_ => Unit` 兜底分支，等价于空操作
  —— `loop { .. break; }` 直接**转不出来**。
- `continue` 在类型检查里被映射成了 `break`，跳出口而不是跳回边。
- 循环头缺 φ：`i = i + 1` 写在循环头里时，`i` 的定义点只有循环头自己 + 入口，
  只统计前驱会漏掉，于是计数器停在入口值。
- 内层循环的累加器只在循环体里定义，却跨着整个内层循环活着 ——
  合流点需要 φ 的判据不能只看「前驱里有几处定义」，得看**活跃性**。
- φ 的 incoming 在寄存器分配里按**定义所在的前驱块末尾**延长，而不是 φ 自己的位置。
  回边上后者在定义之前，算出来的活跃区间会被插入操作覆盖，循环体里刚算出的值
  立刻就「死」了、寄存器被下一条指令复用。

修完之后：迭代支配边界插 φ（Braun et al.）+ DFS 重命名，
循环头的隐式合流、循环出口的合流（`break` 路径）都覆盖到了，
关键边还会拆开，让 φ 的并行拷贝能按边发射。

## 寄存器分配：活跃性分析与栈溢出

原来的线性扫描没有活跃性分析，`alloc_reg` 按 SSA 编号取模映射到固定寄存器池。
于是「同一条语句链上的语句越多越容易串值」—— 这也是早期测试用例必须写成
「辅助函数无分支、断言全放 main、断言控制在 3～6 条」的原因。

现在是 CFG 活跃性分析 + 线性扫描 + 栈溢出：

- 回边活跃区间延长；
- 跨调用存活的值限定 callee-save（顺带修掉了 AArch64 缺 `x19`-`x28` 的问题）；
- 溢出路径覆盖除法 / 取模 / 移位 / 比较的**每一个**操作数位置
  （含 `idiv` 的内存操作数）。

x86-64 的 `emit_param_moves` 也修了一处顺序搬运踩掉尚未读取的源的问题，
改回并行拷贝。

## `comptime`：带终止性保障的编译期求值

```rust
comptime fn fact(n: i32) -> i32 {
    if n <= 1 { 1 } else { n * fact(n - 1) }
}

const SIZE: i32 = fact(5);   // 编译期求值为 120
```

关键设计是**终止性双闸**：递归深度上限 + 求值步数预算。
写一个不收敛的编译期循环会让编译**报错退出**，而不是把编译器挂住。

一个编译期求值系统如果没有这个闸，第一次写非收敛循环的人就会失去整个编译器 ——
所以它不是优化项，是可用性的前提。

目前支持的构造：字面量、算术 / 位运算、比较、逻辑、`let` / `var` / `const`、
赋值与复合赋值、`if`、`while`、`loop`、`break`、`continue`、`return`、
数值转换，以及调用其它 `comptime fn`。不支持 `match` 与结构体字面量
（HIR 目前丢弃这些节点的数据）。

## 浮点：x86-64 与 AArch64

| | 覆盖 |
|:--|:-----|
| f64（x86-64 SSE2） | 常量、`addsd`/`subsd`/`mulsd`/`divsd`、`xorpd` 取负、`ucomisd`+`setnp` 比较、`cvtsi2sd`/`cvttsd2si` |
| f32（x86-64） | `movss`/`addss`…、`xorps` 取负、`ucomiss` 比较、常量携带位宽 `Float(bits, width)` |
| f32/f64（AArch64） | `fadd`/`fsub`/`fmul`/`fdiv`、`fneg`、`fcmp`+`cset`、`scvtf`/`ucvtf`/`fcvtzs`/`fcvt` |

NaN 语义按 IEEE754 处理（比较用 `setnp` / `cset` 的等价条件码组合）。
浮点走**专用栈槽 + XMM / `d0`/`d1` 暂存**，不占用整数寄存器分配器；
浮点实参与返回值按 ABI 走 `xmm0`-`xmm7`（x86-64）/ `v0`-`v7`（AArch64），
与整数实参**分别计数**。

顺带修掉了若干 AArch64 编码 bug：`b.cond` 偏移量、零判定（`cmp x,x`）、
`fneg` 基址、移位基址、`as` 转换（SBFM/UBFM）、取模改线性扫描分配。

## 优化 pass 完整化

常量折叠（整数 + 浮点 + 类型转换）、SCCP 稀疏条件常量传播（含恒定分支折叠）、
死代码消除、死块消除（删块后重编号）、块内 CSE 与全局值编号（覆盖 `Cast` / `Copy`）、
窥孔优化、循环不变量外提、单块函数内联。

还修了一类不好查的问题：**编译确定性**。块号与 φ 编号不再依赖 `HashMap` 的遍历顺序 ——
否则同一份源码两次编译可能得到不同的二进制，缓存和 diff 都无从谈起。

## 属性系统

`#[inline(always)]` / `#[inline(never)]`、`#[repr(C)]` / `#[repr(uN)]` / `#[repr(packed)]`、
`#[link(name, kind)]`、`#[cfg(...)]`、`#[allow]` / `#[deny]`、`#[derive(...)]`、
`#[deprecated]`、`#[test]` 测试桩。

其中 `#[inline]` 参与真实的内联决策，`#[repr]` 参与真实的布局计算 ——
不是装饰。

## 字面量类型后缀

`42u64`、`255u8`、`7usize`、`3.14f32`、`2.0f64`。后缀在词法层就随
`IntLiteral` / `FloatLiteral` token 传递，不符的组合（整数后缀用在浮点字面量上）
在词法阶段就被拒绝。无后缀时沿用上下文推断，默认 `i32` / `f64`。

## 一条边界原则

这一轮里有个一致的做法：**做不到就报错，不要猜。**

- ARM32 / RISC-V / wasm 遇到浮点字面量 → 报错，不静默按整数编码发射。
- 浮点值的取址 / 解引用 → 报错（后端不支持）。
- 两个指针相加 → 报错。
- 32 位目标上的 `i64` / `u64` / `i128` → 类型检查阶段报错。

一个会算错的程序比一个编不过的程序贵得多。后者五分钟能改，前者可能几个月都找不出来。

## 现在的样子

```rust
fn fib(n: i32) -> i32 {
    if n <= 1 { return n; }
    return fib(n - 1) + fib(n - 2);
}

fn main() -> i32 {
    var i = 0;
    var sum = 0;
    while i < 10 { i += 1; sum += fib(i); }
    return 0;
}
```

```bash
zr fib.zr -o fib && ./fib
```

`for i in 0..10` 还不行 —— `..` 区间表达式仍然解析成标识符。
这是当前语法层面唯一的缺口。
