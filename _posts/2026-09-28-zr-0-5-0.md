0.5.0 是 zr 的第一个可用版本。从 `zr build hello.zr` 开始，到把固件烧进树莓派，
中间的每一步都由我们自己的编译器完成 —— 没有 LLVM，也没有运行时依赖。

## 这次发布了什么

- **完整前端** —— 生成器驱动的词法分析器、递归下降 + Pratt 解析器、
  基于 Hindley-Milner 的类型推导、trait 约束求解、NLL 借用检查、模式穷尽性检查。
- **完整中端** —— MIR（基本块 + 终结器）、控制流脱糖、λ 提升、
  SSA 构造（支配树、支配边界、Cytron φ 插入、寄存器重命名）。
- **完整后端** —— 树覆盖指令选择、线性扫描寄存器分配、栈帧布局、机器码发射，
  覆盖 x86-64 / AArch64 / ARM32 / RISC-V 32 / RISC-V 64。
- **容器写出** —— ELF32 / ELF64 / Mach-O / PE-COFF / wasm。
- **11 个目标三元组** —— 三个桌面/服务器平台、三个裸机目标、两个 wasm 目标。
- **标准库** —— core / mem / io / string / slice / collections / async / error / net / simd。

## 为什么自己写后端

最主要的原因是**交叉编译的可控性**。用 LLVM 时，交叉编译需要目标平台的完整
sysroot；自带后端则只需要一个 C 工具链（甚至连链接器都不需要）：

```bash
# 直接产出可烧录的 Cortex-M 映像，不需要 ld、libc、任何 .o
zr firmware.zr --target arm-none-eabi -o firmware.elf
```

第二个原因是**启动方式的自由**。Linux 目标可以直接用系统调用退出进程，
不经过 C 运行时；macOS 与 Windows 转发到 libSystem / kernel32；
裸机目标则停在自循环，由调试器接管。这些差异用 LLVM 加胶水很难表达干净。

## 已知不足

这一版是「框架完整、实现待补」的状态：

- 指令选择尚未覆盖全部 IR 操作码，部分指令序列质量一般。
- 寄存器分配是简化版线性扫描，寄存器压力高时可能溢出到栈。
- 优化 pass 框架已就位，但多数 pass 的实现是简化版本。
- `comptime` 尚未落地。

这些正是 v0.6.0 的工作内容，详见 [路线图](https://zrlang.github.io/community/roadmap/)。

## 试一试

```bash
git clone https://github.com/zrlang/zr.git
cd zr
cargo build --release

echo 'use io::println; fn main() -> i32 { println("Hello, zr!"); return 0; }' > hello.zr
./target/release/zr build hello.zr -o hello && ./hello
```

完整说明见 [安装与第一个程序](https://zrlang.github.io/learn/getting-started/)。
